# Wafer defect classifier on a custom FPGA accelerator

A small neural-network accelerator, designed in SystemVerilog, that runs my wafer-defect classifier on a
$25 **Sipeed Tang Nano 9K** FPGA (Gowin GW1NR-9). Part of the hardware was generated by my own tool,
[rtl-agent](https://github.com/Rapidonot/rtl-agent).

The board takes a wafer bin map over USB and reports which of eight defect patterns it contains. Its outputs
are **bit-for-bit identical** to the integer software model on every test wafer tried (1,000 of 1,000).

## Results

| | |
|---|---|
| Board | Tang Nano 9K (GW1NR-LV9QN88PC6/I5), open-source toolchain |
| Model | 5-layer integer CNN, 29,472 parameters (30.6 KB), 3.39 M multiply-accumulates per wafer |
| Accuracy | macro F1 **0.9406** on the 11,781-wafer test set, multi-label, 8 classes |
| Agreement with software | 1000/1000 random test wafers bit-exact |
| Speed | 3,391,816 clock cycles = **125.6 ms per wafer** at 27 MHz (one multiply-accumulate per clock) |
| Round trip | ~674 ms per wafer, mostly the 6,273-byte transfer at 115,200 baud |
| FPGA distribution | 39 % logic (LUT4), 23 % flip-flops, 26/26 block RAMs |

The model is a distilled, 8-bit version a ResNet-18 model I trained, made small enough for on-chip memory.

| Model | Parameters | Test macro F1 |
|---|---:|---:|
| ResNet-18 (OG) | 11,180,616 | 0.9657 |
| Vanilla CNN (OG) | 3,226,760 | 0.8573 |
| **This model (int8, on the FPGA)** | **29,472** | **0.9406** |

Training and distillation are in [wafer-defect-classifier](https://github.com/Rapidonot/wafer-defect-classifier).

## How it works

```
 Mac (host/wafer_host.py)                     Tang Nano 9K (rtl/)
 ------------------------                     ---------------------------------------------------------------
 224x224 wafer map                            uart_rx -> input map RAM
   -> 2 x 56 x 56 count planes   --- USB -->                 |
   (on-wafer dies, failed dies)               cnn_core: for each layer, channel and pixel
                                                 weight ROM --> mac_acc (1 multiply-accumulate / clock)
                                                            --> 2x2 max pool --> requant (rescale to 8 bit)
                                                            --> other map RAM (ping-pong between layers)
                                              head: sum each channel --> head_unit (8 scores) --> mask
 prediction, scores, cycles      <-- USB ---  uart_tx (38-byte reply)
```

1. **Input.** The host turns each 224x224 map into two 56x56 planes. Each value counts the on-wafer dies and
   the failed dies in a 4x4 block.
2. **Layers.** The core walks through every layer, output channel and pixel. Each clock it feeds one weight and
   one pixel into a single multiply-accumulate unit.
3. **Pooling and rescaling.** After each 3x3 window (and 2x2 pooling where the layer has it), the sum is
   rescaled to an 8-bit value with integer arithmetic only: `clamp((acc * M + 2^(S-1)) >> S, 0, 255)`.
4. **Ping-pong memory.** Results go to the other of two map RAMs, and the next layer reads them from there.
5. **Head.** After the last layer, each channel is summed and multiplied by the head weights to give 8 scores.
   A score above 0 means that defect is present.

**Generated from the model.** Layer count, channel counts, map sizes, pooling and memory sizes all come from
`rtl/gen/cnn_params.svh`, which `tools/export_rtl.py` writes from the model file. Another model of the same
layer type only needs a re-export and rebuild.

### Built with rtl-agent
The five leaf blocks were generated **unattended** by
[rtl-agent](https://github.com/Rapidonot/rtl-agent) using `gpt-6.1-sol`: the model wrote each block's
testbench and design from a plain-English spec. All five passed on the first attempt and are used
unmodified.

| Block | Role |
|---|---|
| `uart_rx.sv`, `uart_tx.sv` | serial link to the host |
| `mac_acc.sv` | multiply-accumulate (uint8 x int8 into 32 bits) |
| `requant.sv` | integer rescaling to uint8 |
| `head_unit.sv` | final 8 scores and the defect mask |

The integration (`cnn_core.sv`, `wafer_top.sv`, `ram_sdp.sv`, `rom_sync.sv`) was written separately,
with claude.

## Build and run

Requirements:
- [OSS CAD Suite](https://github.com/YosysHQ/oss-cad-suite-build), which provides yosys,
  nextpnr-himbaechel, gowin_pack and openFPGALoader.
- Python 3 with numpy and pyserial.

```bash
python tools/export_rtl.py            # model -> rtl/gen/ (already included; only needed for a new model)
tools/build_bitstream.sh              # -> build/wafer_top.fs
openFPGALoader -b tangnano9k build/wafer_top.fs          # load; add -f to keep it after power-off
```

The host script needs the held-out test split from the paper (WM-811K + MixedWM38, 224x224, values 0/127/254):

```bash
export WAFER_TEST_NPZ=/path/to/dataset_15_TEST.npz
python host/wafer_host.py demo --idx 2119     # one wafer: map, prediction, ground truth
python host/wafer_host.py run --n 200         # many wafers: agreement, F1, speed
```

## Notes
- **Feature-map storage.** The feature maps are stored 9 bits wide on purpose. When yosys used its 2-bit-wide
  block-RAM mode for them, the real chip produced rare bit errors that did not appear in simulation. The 9-bit
  mode fixed it (`rtl/ram_sdp.sv`).
- **Speed.** One multiply-accumulate unit keeps the design small. Most of the round trip is the serial transfer,
  not the computation.
